Helm values that scale

  1. 01
    Sane defaults
    values.yaml works for most environments.
  2. 02
    Small overrides
    values-prod.yaml holds only differences.
  3. 03
    values.schema.json
    Fail fast on typos and wrong types.
  4. 04
    No secrets
    Reference them; never inline them.

Deploy and roll back

bash
helm upgrade --install api ./chart \
  -f values.yaml -f values-prod.yaml \
  --atomic --wait --timeout 10m

helm history api
helm rollback api 12

--atomic rolls back automatically if the release fails.

Upgrade habits

Do
  • ✓Upgrade lower environments first
  • ✓Scan for removed APIs
  • ✓Use maintenance windows
  • ✓Keep a rollback node pool
Avoid
  • ✕Skip minor versions
  • ✕PDB minAvailable = replicas
  • ✕Upgrade during a release
  • ✕Ignore deprecation warnings

Production checklist

  • ✓Requests and limits set
  • ✓Probes configured
  • ✓PDB defined
  • ✓2+ replicas across zones
  • ✓NetworkPolicy applied
  • ✓Runs as non-root
  • ✓Image pinned by digest
  • ✓Metrics, logs and alerts
  • ✓Rollback tested

Key takeaway

Structure the chart, rehearse the upgrade, check the list.

  • Small env overrides, schema-validated values
  • --atomic releases with history
  • Upgrade one minor version at a time
